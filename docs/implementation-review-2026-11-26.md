# 半身像工坊 · 完整实现评估

评估日期：2026-11-26。检查对象：根目录 `index.html`，1205 行、58418 字节。评估时源码 SHA-256：`409acac39c73a415f755bce9a63dd4fbef2292edf07c4a6dc8c039dd520e4b2c`。

## 判断

核心产品原型成立。生成、微调、分享和下载已经形成可用路径，程序化 SVG 是最有辨识度的能力。适合保留现有技术基础，小步修复后发布初版。

主要短板是交互契约与状态一致性：用户锁定后头像仍会变、刷新会丢修改、缩略图与主图不一致。手机上调参数时看不到头像，也妨碍核心编辑路径。

本次评估后，所有者于 2026-11-26 确认「轻量头像工坊」方向与 Cloudflare Workers Static Assets 托管，并批准 [开发安排](development-plan.md) 的全部开发安排。本文保留评估时的实现与验证证据；其中处理建议已纳入批准计划，不代表修复已实现。明显手机布局与正式发布仍有所有者验收节点。

## 当前实现与优点

| 维度 | 实现 | 价值 |
| --- | --- | --- |
| 技术规模 | 单 HTML，内联 CSS 与 JavaScript，无框架、后端或外部运行时依赖 | 交付简单，适合静态托管 |
| 图形系统 | 7 槽位、48 选项、6 连续参数、6 颜色通道、6 配色预设 | 兼有离散组合和程序化外观调整 |
| 组合数量 | 离散选项乘积 653184 | 提供足够探索空间，但不代表所有组合都验收过 |
| 风格 | 粗描边插画、纸色与砖红界面 | 视觉语言一致 |
| 引擎边界 | Engine IIFE 与 UI IIFE 分开，支持 CommonJS 导出 | 引擎可在无 DOM 的 Node 环境检查 |
| 可复现 | 同一状态输出同一 SVG，渲染不修改输入 | 有利于分享与自动回归 |
| 结果交付 | 自包含 SVG、1024×1024 PNG、3 种裁切 | 用户可直接带走结果 |
| 分享校验 | 编码长度上限 8000、seed 上限 160、槽位白名单、参数限幅、严格十六进制颜色与布尔锁定值 | 已有异常输入防御 |

6 个参数是蓬松、波浪、长度、刘海、脸宽与肩宽。3 种裁切通过 SVG viewBox 完成。PNG 导出路径为 SVG Blob → Image → Canvas。

## 架构现状

UI 持有 `seed`、`slots`、`locks`、`params`、`colors`、`palette`、`view`。操作更新状态后调用引擎生成 SVG；分享把 UTF-8 JSON 编码为 base64url，放在查询参数 `s` 中。

当前没有自动保存本地草稿、撤销、重做或重置。复制 JSON 存在，但没有对应导入入口。URL 只在显式分享时更新。

实际 11 层顺序：

```text
bgLayer → neck → bodyBack → hairBack → face → hairMain
→ eyes → mouth → bodyFront → extra → topper
```

页面帮助与实际顺序不同。应修说明，不改变已有图层契约。

## 缺陷与影响

| 优先级建议 | 已确认问题 | 证据与影响 | 建议处理 |
| --- | --- | --- | --- |
| 首发前 | 全锁定后随机，发型轮廓仍变化 | 槽位、参数与颜色相同，但 SVG 不同；`randomize` 更换 seed，`hairMain` 使用 seed 生成细节 | 先明确锁定合同，再在状态层区分抽签与绘图输入 |
| 首发前 | 刷新丢失未分享的编辑 | 自定义发色后刷新，恢复默认发色 | 自动保存本地草稿，规定分享与草稿的载入优先级 |

| 首发前 | 手动编辑后缩略图滞后 | 改颜色、参数或槽位时刷新主图，但未统一重建缩略图 | 集中状态更新与渲染 |
| 首发前 | 自定义颜色后预设仍选中 | 自定义配色后仍显示「砖红」选中 | 从实际颜色判断匹配的预设 |

| 首发前 | 随机说明不准确 | 说明写按当前 seed 生成，按钮实际换新 seed | 确定 seed 操作合同并同步文案 |

| 后续 | JSON 复制缺少导入 | 界面无法用复制结果恢复 | 明确用途后补导入或收进高级操作 |

## 建议产品与实现边界

已确认产品方向：面向普通用户的轻量头像工坊，生成、微调并带走一张头像。技术原理宜放进折叠说明，首次进入先说明用途和开始方式。

建议首发保留全部已有部件，接入既定 Logo，修复锁定、状态同步、恢复、手机预览与基础可访问性。账号、云端作品库、服务端生成和批量 API 不作为首发内容；不因建立维护流程就要求先拆文件或引入框架。

已确认静态托管使用 Workers；建议只发布显式生成的应用资源目录。设计文档与 Logo 轮次历史不作为网站资源上传。
