# 自定义部件与 Agent 接入方案

用户于 2026-11-27 确认要支持自定义，并让 Agent 能在现有框架内按层生成内容。下列接口、实现顺序和验收标准是提案。部署者更换站点标题与 Logo 属于独立的站点配置，见 [0.1.0 产品与自建部署评审](product-review-2026-11-27.md)。

## 第一阶段：导入完整头像配置

- 先用现有内置部件做通从 Agent 到编辑器的流程。提供 JSON Schema、带注释的字段说明、最小配置样例及浏览器可预览的示例。CLI 校验与浏览器导入使用同一套规则，给出字段路径和可纠正的原因，例如 `slots.hair` 的值不在可用目录中。
- 将新文件定义为带类型和版本的便携文档。计划兼容当前「复制配置」产生的无版本绘图 JSON，并为用户标明其锁定设置未随文件携带。现有分享与草稿共用 `{ "v": 1, "state": { ... } }`，包含锁定，仍通过各自的恢复入口处理。文件、分享和草稿各自演进，未知文件版本明确报错。
- 校验成功后在临时状态中展示预览，用户确认后才应用并更新草稿。取消或失败时保留当前草稿。沿用 `seed` 与 `drawingSeed` 的独立职责，同一份完整配置应可重现画面。

## 第二阶段：导入单层自定义部件

- 从 `topper` 开始，随后用相同约束验证 `extra`。部件文件包含类型、版本、稳定 ID、名称、目标槽位、可用锚点和图元列表。用户可以导入、预览、替换或恢复内置部件。Agent 可从本地模板和 CLI 入手，待格式稳定后再评估 API 或 MCP。
- 引擎使用 600×600 画布并负责 11 层顺序、锚点变换、裁切与输出。每槽位文档公布锚点坐标及随连续参数变化的规则。预览和导出共用 `half`、`bust`、`head` 三种裁切，查看后两种裁切是否会遮住部件。部件通过 `ink`、`skin`、`hair`、`cloth`、`accent`、`bg` 六个颜色通道引用当前配色。
- 从有限图元开始，例如圆、椭圆、矩形与由结构化命令组成的路径。校验有限数值、坐标和尺寸范围、命令类型、图元数量、路径复杂度及文件大小。由引擎生成 SVG。文件只含数据和内嵌图元，导入拒绝脚本、事件属性、原始 SVG/HTML、URL 和外部资源。
- 便携文件携带它引用的自定义部件。草稿、文件和后续分享必须明确如何恢复相关资源。超过分享链接容量时引导导出文件。首个交付验收包括一份 Agent 生成样例、坏字段定位、三种裁切、换色、重开后恢复及 PNG/SVG 同画面。

## 第三阶段：扩展成对图层

- 发型同时覆盖 `hairBack` 和 `hairMain`。内置 `bald` 还会让 `face` 绘制头皮弧，扩展前要明确该规则如何随自定义发型处理。衣服同时覆盖 `bodyBack` 和 `bodyFront`。成对片段作为一个槽位部件一起校验、预览、替换和锁定。
- 验收使用已有 SVG 基线，另测成对片段缺失、三种裁切中的遮挡、参数变化和锁定行为。全锁随机仍要求 SVG 逐字节一致，锁住发型时保留 `drawingSeed`，同时保留未锁参数和颜色对外观的现有影响。

当前引擎层序、状态字段和裁切数据见 [设计基线](DESIGN.md)。
