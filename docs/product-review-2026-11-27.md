# 半身像工坊 0.1.0 产品与自建部署评审

2026-11-27。评审基线 `147a5adafc311bfa79abbe49f9a3dffad1717864`。Neon、DeepSeek V4.1 Flash 与 Grok 均已提交独立评审和交叉复核。`0.1.0` 的上线与公开地址验收记录见[发布指南](RELEASING.md)。本文提出下一轮开发范围，现行产品行为以[设计基线](DESIGN.md)为准。

## 结论

首版的生成、锁定、微调、草稿、下载和分享已组成完整流程。普通用户最急需的是**看分享时保住自己的草稿，编辑时看得到头像，做完后就近下载**。第三方部署已具备静态产物与资源隔离，主要缺口是**统一的品牌配置和一条独立于官方发布门禁的自建路径**。建议先做编辑保护，再做首屏与预览，随后交付自建配置。源码再分发与导出图用途分别由所有者决定。

## 现有实现与限制

- agy 的 Neon 在本地用浏览器模拟桌面、平板与窄屏，测了首次打开、草稿恢复、链接回退和 SVG/PNG 下载。生成与微调即时反馈。`375px` 和 `390px` 两种窄屏视口没有横向溢出，紧凑粘性预览支持边调边看。
- Pi 的 DeepSeek V4.1 Flash 在隔离目录从干净检出开始，跑通自检、构建、本地预览和官方阶段门禁。现有 `dist/` 只包含五个文件，预览实测 `docs/`、`rounds/`、缺失资产和未知路径返回 `404`。
- Grok 对照源码、测试、发布文档及公开资产摘要。评审基线和正式发布的提交不同，已核对的三份公开资产字节一致。开发安排、可视化概览和部分历史说明仍有「未发布」「未接 Logo」等旧表述，容易把接手者带回首发前的步骤。

## 面向用户的改进顺序

| 顺序 | 现有证据 | 改动与验收 |
| --- | --- | --- |
| 1. 保护草稿和编辑结果 | 有自己的草稿时打开他人链接，切换一次裁切便调用 `noteEdit()` 保存他人的状态。无效或不支持的分享链接走默认形象，同样可能在切换裁切时覆盖草稿。点例图也会立即替换当前作品及锁定状态。 | 分享预览期间保留原草稿。提供「编辑这张」和「回到我的草稿」，明确确认后才替换已有草稿。明确接管和载入例图后可恢复一次，恢复时同时还原作品和锁。随机和重置的通用撤销另行评估。覆盖有效、旧版、无效和未来版本分享及保存失败。 |
| 2. 首屏和实时预览 | `390×844` 首个部件区约在页面 `y=974px`。`900×900` 调参时画布滚离视口，CSS 在 `721–1080px` 区间缺少停靠预览。`1440×900` 滚到底时也观察到桌面画布被裁切。 | 缩短首屏说明，前置发型或五官编辑，保留已验收的窄屏紧凑预览和桌面双栏方向。用 `375×667`、`390×844`、`900×900`、`1280×768` 和 `1440×900` 检查首屏、长页面底部及编辑到下载的连续性。 |
| 3. 锁定、导出与信任 | 全锁时依然改变种子，画面不变且无反馈。手选部件、滑块、预设和手改颜色的自动锁定行为不同。光头时四个发型滑块可动，画面不变。PNG、SVG、复制配置同一层级，复制的 JSON 缺锁定字段。 | 显示锁定数和全锁反馈，明确失效控件，给取色器足够触控区。把「下载 PNG」作为主入口，SVG 和 JSON 放入次级操作。用短说明讲清浏览器渲染、草稿存储位置及链接携带配置。遇到草稿保存失败或分享格式错误时，给用户时间读完并提供恢复入口。 |

草稿修复要保留现有 `v: 1` 和无版本链接。注意「复制当前分享链接」也会更新地址栏，不能仅用地址是否带 `s` 来判断是否在查看别人的作品。应显式记录页面是从有效分享进入还是正在编辑本地作品，并区分预览、提交与提交失败。分享 URL 携带配置，隐私文案应说明这个事实。

Grok 复查确认，首版合同已把裁切和载入示例定义为会保存的编辑，撤销也明确排除在首发范围。Neon 认为它们对用户的影响值得优先处理。这里按产品风险将草稿保护排在第一位，先改设计合同和回归用例，再实现分享预览。通用撤销可以跟进，首个合并切片优先交付明确接管与替换后的恢复入口。

DeepSeek 用真实状态层和从页面提取的事件处理函数复现了无效链接覆写草稿。在隔离原型中，分享态只切裁切时保留原草稿和分享地址，已有 46 项自检通过。该原型在首次内容编辑时自动接管并提示，仍会写入原草稿。正式方案建议保留明确确认、返回和恢复入口，并用浏览器验证完整交互及提示。普通本地编辑的裁切继续保存在草稿中。

验证范围以[当前设计合同](DESIGN.md)为基准。桌面和模拟窄屏已有证据，iOS Safari、Android Chrome、微信内置浏览器、实际跨应用粘贴、系统下载保存和读屏还需实测。社交平台的圆形裁切预览、JSON 导入和动态头像分享图可另行评估。

## 第三方部署提案

**保留根 `index.html` 的默认内容和直接打开方式。** 建议增加一份精简的 `site.config.json` 和一份示例。第一版配置只覆盖页头站名、浏览器标题、描述、Logo 和 favicon。新配置通过显式的自建构建入口生效，根页面直接打开时显示默认品牌。后续可用公开站点地址与栅格分享图配置固定站点卡片，构建时生成静态标签。分享链接仍通过查询参数还原头像，站点卡片展示产品预览图。参考 [Open Graph 基础字段](https://ogp.me/#metadata)。

| 层次 | 准备交付的能力 |
| --- | --- |
| 源码与品牌 | 在 `index.html` 标记可配置位置，保留直开时的默认内容。构建期校验和转义配置值，用同一渲染函数生成并校验 HTML。站点资产显式列入白名单，缺文件直接报错。官方 Logo 母版保留在 `rounds/R05-2026-11-26/shu.svg`。 |
| 自建产物 | 提供从样例配置、放入图标、构建、自检到本地预览的指南。只上传生成的静态目录。通用产物验证检查白名单、引用与哈希，能从改过品牌的工作目录运行，也覆盖没有 Git 元数据的源码包。官方母版校验与自建品牌校验分别运行。 |
| 官方发布 | 保留 Cloudflare Workers Static Assets、`cf`、阶段清单、干净提交、域名白名单和默认产物的逐字节校验。官方部署参数由发布入口读取。自建构建与校验通过显式入口运行，默认发布产物继续使用当前的打包与检查语义。 |

DeepSeek 的本地原型证实构建时可替换品牌文本、图标路径和 HTML 元数据，现有 46 项自检与正式阶段校验可通过定向调整。原型中的分享图仍指向 SVG，栅格卡片与平台抓取待验。互审确认，在两份发布配置中同步改用自有域名即可通过校验，测试夹具可继续使用示例域名。`verify:ci` 只校验已有的 `dist/`，能检测现有页面和白名单资产的字节漂移。`verify:ci` 与 `verify:release` 要求干净 Git 工作区。候选阶段的 `verify:dist` 已在无 Git 的实验副本通过，该命令在当前 `release` 树按预期拒绝。独立自建入口应兼容源码包，并将 `site.config.json` 与品牌资产纳入产物漂移检查。

Neon 认为直接改 HTML 与同名图标的短路径更容易上手，Grok 主张保住官方逐字节门禁。我建议把直接替换保留成文档中的快速参考，配置化只服务显式自建入口，并复用现有资产白名单逻辑。自建指南要让部署者知道改了哪些文件、预览哪个目录、最终上传什么。站点改名、换图和加卡片属于自建交付，分享卡缺席无需占用普通用户修复的首位。上线前要在目标聊天平台点回带 `?s=` 的真实链接，确认头像还能还原。根路径元数据是否会影响参数保留，目前没有平台实测。

**自建验收。** 在隔离目录用陌生品牌换标题、描述、Logo 与 favicon，访问首页并检查浏览器标签、两种图标、可选分享图及资源响应。连续构建产物应可重现，改配置后校验旧产物应报漂移，配置缺件应指出具体文件。检查旧品牌资产无残留、内部路径返回 `404`、官方品牌仍通过发布门禁、四个固定 SVG 基线及 11 层顺序通过。用已有链接和浏览器草稿做迁移烟测。能否开展同源多实例部署单独验收，默认草稿键先维持兼容。

## 小步交付与复用经验

1. **编辑安全**单独提交，先把分享裁切覆盖和例图覆盖做成回归用例。首个切片验收独立的分享预览、明确的草稿替换和一次恢复，再按需要增加通用撤销。
2. **产品体验**单独提交。让执行者实现首屏、预览与导出路径，另一模型在约定视口实际操作，指挥核截图和状态。真机结果记录设备、浏览器、操作与结果。
3. **自建配置**单独提交。先交最小品牌配置与通用验证，再接可选分享卡。文档修正旧发布状态并把现行发布指南作为入口。确定源码与导出图使用范围后补对外文字。

首发可复用的运维经验已沉淀在 wiki 的《半身像工坊 0.1.0 首发复盘》《Cloudflare Workers 静态资源发布流程》和《指挥者运行手册》。本轮补充一个验收分工经验：**自建烟测从普通部署者的输入开始，官方发布核对从指定干净提交开始**。构建成功、产物正确、平台部署完成与公开地址实际使用分别保留证据。编排用原有 Orca 会话收回执并交叉复核，本轮三位执行者使用独立工作区终端。
