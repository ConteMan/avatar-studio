# 本地作品与编辑历史

2026-11-27 所有者确认方案及两阶段交付。目标是让用户随时找回之前做的头像，并在单个作品内撤销或重做。第一阶段由 GitHub Issue #26 跟踪，第二阶段由 Issue #27 跟踪。

## 使用方式

「我的作品」从编辑器打开。列表按最近编辑排序，显示缩略图、标题、更新时间和步骤位置。点开即可恢复作品及其当前步骤。新作品自动命名，支持重命名。手机上优先保留编辑和下载空间，作品列表独立打开。

| 操作 | 结果 |
| --- | --- |
| 打开首页 | 恢复上次编辑的作品及其步骤位置。空库在首次有效编辑时建立记录。 |
| 打开有效分享或载入示例 | 先进入预览。点击「保存为新作品」或首次有效编辑时新建独立记录。返回原作品、查看和下载均保留原作品。 |
| 打开无效或不兼容的分享 | 提示失败并显示之前的本地作品，保留其内容、历史和选择。 |
| 编辑已保存作品 | 自动保存。随机生成、切换部件、换色、修改裁切和锁定状态各按一次完整操作记一步。 |
| 拖动滑块或连续调色 | 一次连续操作合并为一步，只持久化最终状态；同一操作的中间快照不进入历史。 |
| 撤销或重做 | 在当前作品内移动到相邻步骤，刷新或切换作品后保留各自位置。撤销后继续编辑时，替换当前作品的重做分支。 |
| 键盘操作 | 焦点不在文本输入时，`Ctrl/⌘+Z` 撤销，`Ctrl/⌘+Shift+Z` 或 `Ctrl+Y` 重做。工具栏按钮可用 Tab 聚焦、Enter/空格触发，并提供操作名与禁用原因。 |

编辑区工具栏在裁切切换旁提供「撤销」「重做」与 `第 n/m 步` 标记。工作栏、作品列表和按钮标题同时显示当前位置或下一步操作名。文本输入、作品重命名和对话框内保留浏览器原生撤销，不劫持快捷键。没有可撤销或可重做步骤时按钮禁用并说明原因；发生跨标签冲突时暂停历史操作，先处理冲突。

分享或示例的原始状态是新作品的第零步，第一次修改可撤销回它。重复打开同一分享只预览，主动保存或编辑可建立另一份作品。复制当前作品的分享链接不会改变它的身份，已复制的链接仍只包含生成时的头像状态。

## 历史与步数语义

- 每份作品保存完整快照序列 `snapshots` 与当前位置 `currentIndex`，撤销/重做只在当前作品内移动位置，不跨作品。
- 每份快照保存经现有状态模型校验的完整头像配置，复用 `persistableState()` 的字段，包括 `drawingSeed` 与 `locks`，并带简短操作名和时间。缩略图由快照实时绘制，不保存导出图片。
- 一次完整动作记一步。滑块、颜色选择等连续输入按同一控件合并为一次，拖动过程中只替换当前步骤，结束输入后落盘最终值。
- 与当前步骤完全等值的提交直接跳过，不增加修订号。完整动作回到紧邻上一步时收束回上一步，不保留重复快照。
- 撤销后继续编辑会从当前位置截断，替换原重做分支。
- 每个作品保留最近 50 个可撤销步骤；再加上当前步骤，最多持久化 51 份快照。达到上限后继续编辑只丢弃最旧步骤，作品、当前位置和最新快照始终保留。完整作品库备份与更长历史不在本阶段范围。

## 持久化与恢复

- 用 IndexedDB（数据库 `avatar-studio.library`，版本 `1`）保存作品元数据、当前快照位置和有界的快照历史。作品历史使用独立的存储版本（`STORAGE_VERSION = 1`），继续读取现有分享格式和旧链接；分享内容不含作品列表或操作历史。
- 第一阶段写入的 1–2 份快照记录可直接读取和继续编辑；超过 51 份的旧记录在加载时按当前位置裁剪，保留当前步骤与最新快照。
- 首次成功迁移时，将 `avatar-studio.draft` 校验后建立为「旧草稿」。迁移记录（`meta.migration.legacyDraft`）和作品在同一 IndexedDB `readwrite` 事务写入，重复启动不会重复导入。迁移失败仍可读取原草稿。保留旧键以支持回退，后续编辑写入作品库。
- 写入失败时明确显示「更改尚未保存」，保留编辑画面、本标签完整分支和上一次成功保存的版本，并提供重试与配置 JSON 导出。失败后刷新会重新读取暂存并继续处理，不再静默回到旧版本。预览转为作品后，只有保存成功才移除 URL 中的分享参数。
- 多标签页按作品 ID 和修订号（`rev`）校验写入。撤销或重做同样提交完整历史与 `rev`。遇到同一作品的新版，提示重新载入、保存为副本或导出；保存副本使用由原作品与本地历史确定的 `workId`，连点、重复触发或并发请求只会建立一份副本。副本实际落盘后才清理暂存，失败保留原作与待保存分支，可再次重试。冲突栏在刷新后仍会恢复，重新载入新版属于用户明确放弃本页分支，只有此时直接清理对应暂存。
- 卸载、切页或隐藏前已提交到队列或暂存的编辑，会在下次启动按标签归属回放。完整历史暂存包含快照与当前位置，只有写入它的 `tabId` 可以回放；刷新、前进后退沿用原归属，新标签、`window.open` 或复制标签获得新的归属。仅凭 `tabId` 与导航类型不足以区分复制标签、BFCache 恢复和正常刷新，因此启动时还通过 Web Locks 为 `tabId` 持有活跃文档锁：拿到锁才自动回放；锁被占用、API 不可用或无法在限定时间内确认时，不写原作、不删除暂存，改为显示「无法确认未保存编辑的归属」的安全恢复栏。暂存的自动查询、恢复、比较和清理都严格使用当前确切的 `tabId`，没有本 id 记录时不会回退读取其他标签的旧格式单条或 `byTab` 记录；因此普通新页、使用已保存版本/保存副本后的页面不会反复卡在旧暂存提示。旧格式（无 `snapshots`）暂存仍可在同一 `tabId` 下受控恢复；归属未确认时在同一安全恢复栏中保存副本或导出，其他 id 的记录保持不被消费，必要时由人工按原 id 处理或等待过期。清理使用「读到的暂存是否仍是当前暂存」的比较，失败、旧事务完成或异步回调不能删除较新的暂存。
- 没有待保存暂存、但拿不到活跃锁的新文档会先分配新的 `tabId` 并取得新锁，作为普通新会话继续编辑；这避免继承同一身份后首次编辑改写原标签正在查看的作品。没有 Web Locks 时，没有待保存普通新会话仍可正常编辑；有暂存时进入同一安全恢复栏。所有普通作品写入和暂存写入都要求当前文档持有写入租约，而不只是在启动回放时检查。
- 归属不明时，安全恢复栏只提供「保存为副本」「使用已保存版本」与「导出配置 JSON」：保存副本成功后才换用新的本页 `tabId` 继续编辑，原标签暂存保留不删；改名和切换作品也要求确认归属，歧义或离页期间不会调用 `renameWork` 或更新当前作品元数据。保存副本或使用已保存版本后，编辑状态、步骤、画面选中与分享 URL 会同步到副本/已保存版本，不保留歧义期间的临时点选。使用已保存版本只切换本页身份，同样不删除原标签分支。关闭其他使用同一分支的标签后刷新，新页面重新取得锁并自动恢复暂存；锁不可用（如不支持 Web Locks 的浏览器）时始终走这一保守路径，同一标签的正常刷新也需保存副本或导出，而不是静默写回原作。
- IDB 已落盘同一历史时幂等清理；`rev` 已被其他标签推进且内容不同时拒绝覆盖，并在刷新后继续展示冲突恢复栏。启动回放遇到配额或存储不可用时恢复本页完整分支与重试栏；若连 `localStorage` 暂存也无法写入，工作栏会明确提示刷新会丢失当前分支，并保留配置 JSON 导出入口。`pagehide` 会撤销写入租约、取消定时保存和在途 IndexedDB 写事务；脚本若继续运行也不能再写库或新暂存。BFCache 恢复时重新取得锁，并把被中间导航改写的 `sessionStorage` tab id 恢复为内存身份；取不到锁则进入安全恢复栏。`pagehide` 异步写不当作持久化保证，浏览器强杀时仍可能丢失最后一笔未落盘编辑。
- 「我的作品」说明记录保存在当前浏览器和站点。更换浏览器、站点域名或清除站点数据后，可通过导出的配置恢复单个头像。含完整历史的作品库备份后续单独设计。

## 推进与验收

1. **第一阶段（Issue #26，已合并）**：作品库、旧草稿事务迁移（含分享预览态下迁移失败的可见提示与独立重试）、作品切换、行内重命名、跨标签页修订冲突保护、写入失败恢复、卸载/切页窗口待保存编辑按标签暂存回放（独立键 `avatar-studio.pending-edit`，按 `tabId` 归属隔离、确定性 `workId` 幂等去重、`rev` 冲突保护，保留旧键 `avatar-studio.draft` 不删改）以及分享和示例预览另存。第一阶段保存新作第零步与当前快照（最多 2 步，改回第零步同值时收束回 `currentIndex = 0`），不持久化每次编辑的完整历史，为第二阶段撤销/重做预留兼容结构。窄屏在 390×844 与 320×640 模拟宽度下均实测单行页头（65px）无横向溢出，真机待后续实测。
2. **第二阶段（Issue #27）**：接入每个作品的撤销、重做、完整步骤历史与连续编辑合并。每份作品最多 50 个可撤销步骤（51 份快照），撤销/重做、刷新恢复、同作品跨标签冲突、旧格式暂存回放和写失败重试均沿用既有校验与 IndexedDB 保存路径。冲突、配额失败和启动回放失败会保留本标签完整分支与当前位置，连续刷新仍可处理；完整历史只由持有活跃文档锁并拥有暂存的标签回放，归属不明时只允许安全副本、已保存版本或导出，副本使用确定 `workId` 防止重复建档。桌面与窄屏提供可发现的工具栏按钮和键盘快捷键，处理文本输入、焦点与空历史。
3. 本地预览验收后，再安排正式发布。覆盖桌面与手机操作、键盘焦点、存储不可用、配额不足、并发修改、旧分享和旧草稿。

主验收路径为编辑 A，打开分享 B 并编辑另存，载入示例 C 并另存，刷新后恢复 C，再从列表打开 A（并补测 B 的撤销、重做及重做分支替换）。迁移失败后重试应只生成一份旧草稿，预览重复打开不应增加作品数。
