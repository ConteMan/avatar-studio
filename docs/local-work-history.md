# 本地作品与编辑历史

2026-11-27 所有者确认方案及两阶段交付。目标是让用户随时找回之前做的头像，并在单个作品内撤销或重做。第一阶段由 GitHub Issue #26 跟踪。

## 使用方式

「我的作品」从编辑器打开。列表按最近编辑排序，显示缩略图、标题和更新时间。点开即可恢复作品及其当前步骤。新作品自动命名，支持重命名。手机上优先保留编辑和下载空间，作品列表独立打开。

| 操作 | 结果 |
| --- | --- |
| 打开首页 | 恢复上次编辑的作品。空库在首次有效编辑时建立记录。 |
| 打开有效分享或载入示例 | 先进入预览。点击「保存为新作品」或首次有效编辑时新建独立记录。返回原作品、查看和下载均保留原作品。 |
| 打开无效或不兼容的分享 | 提示失败并显示之前的本地作品，保留其内容、历史和选择。 |
| 编辑已保存作品 | 自动保存。随机生成、切换部件、换色、修改裁切和锁定状态各按一次完整操作记一步。 |
| 撤销或重做 | 在当前作品内移动到相邻步骤，刷新后保留所在步骤。撤销后继续编辑时，替换当前作品的重做分支。 |

分享或示例的原始状态是新作品的第零步，第一次修改可撤销回它。重复打开同一分享只预览，主动保存或编辑可建立另一份作品。复制当前作品的分享链接不会改变它的身份，已复制的链接仍只包含生成时的头像状态。

## 持久化与恢复

- 用 IndexedDB（数据库 `avatar-studio.library`，版本 `1`）保存作品元数据、当前快照位置和有界的快照历史。每一步保存完整、经现有状态模型校验的头像配置，复用 `persistableState()` 的字段，包括 `drawingSeed`。滑块、颜色选择等连续操作只记录最终提交，重复快照跳过。快照保留简短操作名，供撤销和重做提示使用。
- 作品历史使用独立的存储版本（`STORAGE_VERSION = 1`）。继续读取现有分享格式和旧链接，分享内容不含作品列表或操作历史。缩略图从已保存的配置生成，作品记录不依赖导出的图片文件。
- 首次成功迁移时，将 `avatar-studio.draft` 校验后建立为「旧草稿」。迁移记录（`meta.migration.legacyDraft`）和作品在同一 IndexedDB `readwrite` 事务写入，重复启动不会重复导入。迁移失败仍可读取原草稿。保留旧键以支持回退，后续编辑写入作品库。
- 写入失败时明确显示「更改尚未保存」，保留编辑画面和上一次成功保存的版本，并提供配置 JSON 导出。预览转为作品后，只有保存成功才移除 URL 中的分享参数。
- 多标签页按作品 ID 和修订号（`rev`）校验写入。遇到同一作品的新版，提示重新载入或将本页编辑保存为副本，避免旧标签页覆盖已保存进度。
- 「我的作品」说明记录保存在当前浏览器和站点。更换浏览器、站点域名或清除站点数据后，可通过导出的配置恢复单个头像。含完整历史的作品库备份后续单独设计。

## 推进与验收

1. **第一阶段（Issue #26）**：作品库、旧草稿事务迁移（含分享预览态下迁移失败的可见提示与独立重试）、作品切换、行内重命名、跨标签页修订冲突保护、写入失败恢复、卸载/切页窗口待保存编辑按标签暂存回放（独立键 `avatar-studio.pending-edit`，按 `tabId` 归属隔离、确定性 `workId` 幂等去重、`rev` 冲突保护，不把 `pagehide` 异步写当作保证，保留旧键 `avatar-studio.draft` 不删改；边界为浏览器强杀或 `localStorage` 不可用/满额时无法依赖暂存恢复）以及分享和示例预览另存。第一阶段保存新作第零步与当前快照（最多 2 步，改回第零步同值时收束回 `currentIndex = 0`），不持久化每次编辑的完整历史，为第二阶段撤销/重做预留兼容结构。窄屏在 390×844 与 320×640 模拟宽度下均实测单行页头（65px）无横向溢出，真机待后续实测。
2. **第二阶段（后续）**：接入每个作品的撤销、重做与连续编辑合并。建议起点为每个作品保留最近 50 步，按体验与容量测试定稿，达到步数上限时保留作品和最新编辑。
3. 本地预览验收后，再安排正式发布。覆盖桌面与手机操作、键盘焦点、存储不可用、配额不足、并发修改、旧分享和旧草稿。

主验收路径为编辑 A，打开分享 B 并编辑另存，载入示例 C 并另存，刷新后恢复 C，再从列表打开 A（第二阶段补测 B 的撤销、重做及重做分支替换）。迁移失败后重试应只生成一份旧草稿，预览重复打开不应增加作品数。
